### 2.1 CPU 与 NPU 分别承担什么

| 环节 | 实际分工 |
| --- | --- |
| NPU | 每个去噪步骤执行 `transformer_blocks[0].attn.to_q` 的全部256行，以16个M16 tile完成；4步共4次请求、64个tile |
| CPU | 分词、两个CLIP、除该 Q 投影外的全部DiT、Attention其余部分、归一化／激活、scheduler、VAE、边界转换、行组装及传输组织 |
| 精度 | CPU管线主要FP32；NPU投影输入／权重／输出BF16；没有据此完成W8／W4或INT8／INT4整模型量化 |
| 回退 | 指定NPU计算段记录 CPU fallback=0、host implementation=0；显式安排在CPU的其他模块不会被计作“回退” |

NPU返回值真正进入了后续去噪，不是旁路探针。但是“每步调用NPU”“计算段零回退”都不等于NPU承担全模型主要计算。

### 2.2 已测量与未测量的 CPU 资源

- 生成主进程历史峰值 RSS 为 **18,814,324 KiB，约17.94 GiB**。这是该进程生存期峰值，不含远端 worker 总和，也不是整机内存占用。
- PyTorch算子内线程配置为 **8**，不是实测固定占满8个物理核心。
- 完整请求墙钟约 **99.798秒**，包括加载、CPU、NPU、传输和收尾，不是纯NPU或CPU独占耗时。
- 没有 CPU 利用率、CPU user/system时间、CPU/NPU耗时比例和全模型算量分母，不填写百分比或加速倍数。

四次历史 Q 请求正常关闭，不代表扩大版作业已经结束，尤其不能用旧图的关闭回执推断当前设备状态。

## 3. 其他成果与未闭环事项

### 3.1 真实 Q 单元的数值记录

[公开指标](ref/experiment_results_20261115/q_projection/metrics.json)记录 `[16,1536]` BF16输出共24,576个元素：24,573个位一致、3个不同，最大绝对误差 `0.000244140625`，RMSE `1.557344391530825e-06`，最大BF16 ULP距离4。

这些是历史单元结果，不是整图精度或扩大版结果。尚无预先批准的通用容差，继续保持 `METRICS_ONLY / NOT_EVALUATED_NO_APPROVED_TOLERANCE`。

### 3.3 扩大至392个Linear：仍为UNKNOWN

已有候选实现清点392个Linear，BF16参数预算 `4,486,127,744` 字节，池配置8 GiB；它们是代码预算与配置，不是当前设备实际驻留或真实覆盖量。

当前仍缺：同一次任务的最终回执、实际调用模块清单、扩大版图片、错误或关闭结果。连接不可用既不证明成功，也不证明失败或停止；**不得重新启动同一任务来代替核实原任务结局**。

即使这些Linear后续全部执行，Attention QK／softmax／PV、归一化、激活、CLIP、VAE等仍需逐项核实，不能称作完整DiT或全模型迁移。

## 5. 恢复后从哪里继续

以下是后续计划，不是本次已经执行：

1. 从获授权的登录入口恢复连接，先按当前实际错误定位一次，不重装或重启来猜原因。
2. **优先核对原扩大版任务结局**：持久任务ID、已有进程／日志、最终结果、实际调用和资源关闭；避免重复启动或覆盖旧目录。
3. 确认唯一设备操作者、有效共享条件与实际运行环境；历史健康和锁回执不能替代现场状态。
4. 对明确失败或未启动的任务修复最小阻塞，优先复用稳定组件、权重、参考和分发回执；不为恢复连接重复下载模型。
5. 新的扩大覆盖结果须留下同一次请求的图片、设备返回值进入模型的证据、CPU/NPU分工、误差／质量与资源关闭记录。
6. 完整核心计算迁移及正式质量验收仍是目标；只有正确性基线成立后才报告同条件性能对照。

两条工作线继续分工：NPU覆盖与设计线负责实际设备推进，经验归档线整理方法与证据；连接受阻期间不新增并行设备操作者。
