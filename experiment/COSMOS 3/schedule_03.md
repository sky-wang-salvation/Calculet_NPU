## 2. Nano 历史里程碑：保留来源等级

以下数值均回引 [schedule_02 的执行侧报告](schedule_02.md)，本次未访问原始设备日志、未独立复测。读取了阶段文档，不等于重新观察硬件。

| 里程碑 | 历史报告值 | 结论边界 |
| --- | --- | --- |
| 设备打开与 BF16 往返 | `2 KiB` 数据逐字节一致，测试范围 CPU 回退为零 | 对应数据通路可工作；不是模型计算、带宽或峰值性能。 |
| 原始基础探针 | 七项中六项通过；原生因果注意力因 `aten::tril.out` 缺失失败 | 不能写成原始七项原样重跑全部通过。 |
| 项目内方形因果注意力 | 最大绝对误差约 `0.0014`；未来值扰动隔离检查通过；`84` 次设备发射；该测试回退为零 | 是另一次特定实现/输入的适配结果，不是通用算子补齐或 rolling 完成。 |

原始通过项为加法、两种矩阵乘、Softmax、LayerNorm 与无掩码注意力。具体 shape、dtype、容差和逐项误差没有在公开快照中完整列出，本次不补造。

`84` 次设备发射不是加速比；`0.0014` 是单实例观测值，不是整个模型的质量阈值。局部计算零回退不能外推整应用零 CPU。

## 3. 最近讨论推进了什么，哪些仍只是目标或方案

### 3.1 完整生成请求已明确，但没有完成回执

相关后续对话提出：参考 SD3.5 的真实部署经验，让 Cosmos 使用真实权重生成测试素材；会话同时讨论了采用双环境、真实张量桥接的 HYBRID 首轮路径。

这是**需求与推进声明的归档**，不是本次新执行或完成验收。当前可读材料中未取得新的 Cosmos：

- 完整权重与模型加载完成记录；
- 完整请求 summary、实际输入及固定模型 revision 的对应证据；
- NPU 返回值进入真实生成链的 trace；
- CPU/NPU 分工、计算回退和资源关闭回执；
- 生成的视频文件及其质量验收。

指定本地 Cosmos 资料目录的定向检索没有发现这些新增材料，但这只说明本次可取得的证据范围，**不能据此断言远端或其他工作区绝不存在结果**。当前新完整请求的完成状态记为“未核验”，不写成成功，也不凭缺少回执判为运行失败。

### 3.2 本地 Linux 离线路线仍需接入契约

已有讨论明确区分两条路线：

```text
Rust / SDK 模板 → CalVX → docc → calbin → 板端运行合同

现有 Python 适配 → PyTorch / Dope 后端 → 实际运行时
```

不能把现有 Python 适配直接交给 `docc` 就认定得到完整 Cosmos calbin，也不能未经核对就要求重写整个模型。

本次没有取得新的 Cosmos 本地构建、打包、加载成功日志；工具存在、tiny 示例或静态命令模板不等于该模型已经构建。旧对话中的磁盘余量也不作为本次当前资源测量，存储与内存条件需在实际准备时重新核对。

### 3.3 离线注意力参考属于待验证方案

后续讨论提出的参考方案包含：

- 显式分段、GQA、可见性与重复计数语义；
- 分段 softmax / LSE 合并和 dense score 加 `log(count)` 的交叉参考思路；
- 矩形 Q/K、gap、空可见行、重复项和极端 logits 等边界测试。

这是计划的技术范围，不代表已存在完整实现和通过结果。拟议的 `reference.py`、`test_reference.py`、`run_probe.py` 等名称也不应包装成当前已经交付的可运行程序。

即使离线数学参考以后通过，仍需另行证明设备实现、真实模型接入与最终视频；它不是缩减整模型目标的替代品。

## 4. rolling / gapped replay 仍是实质缺口

方形因果注意力不能替代完整 Sim-Auto rolling 后端。后续实现与验收需保持：

| 语义或环节 | 需要核验的内容 |
| --- | --- |
| 分段与变长 | Q/K 布局、历史缓存、gap 行和分段范围。 |
| 多摄像头可见性 | 同摄像头历史、跨摄像头窗口、逐摄像头 caption。 |
| GQA 与重复计数 | 头部关系和分支重数；简单布尔 mask 不自动保留计数语义。 |
| FP32 LSE 合并 | 分段稳定合并、空段和极端 logits；不把 BF16 输出当作已有 FP32 LSE 出口。 |
| 空可见行 | 按参考合同返回零输出与负无穷 LSE等约定结果。 |
| 模型接入 | 返回值进入真实 rolling 生成链，而不是只完成独立注意力探针。 |

既有源码/SDK调研发现可复用模板，但“有候选宏”“有原语声明”“有接口说明”不能替代实际编译和数值验收。完整 CUDA/FA4 路径、环境版本差异、模型构造和视频 VAE 仍需逐层解决，不能通过静默放宽 CPU 回退隐藏缺口。

已有基线将首个完整请求限定为官方允许的 RGB-only、480p。本次没有修改或验证该合同，也不新增 LiDAR 或性能目标。

## 6. SD3.5 经验如何复用到 Cosmos

| 可复用的方法 | 不可直接照搬的结论 |
| --- | --- |
| CPU 生成环境与厂商 worker 环境隔离 | SD3.5 依赖版本适用于 Cosmos。 |
| 固定模型和实际执行源码身份 | 换模型目录即可运行。 |
| 将真实张量送至 NPU，并让返回值进入 forward | 跑一个旁路探针就证明 NPU 参与素材生成。 |
| 分别记录 CPU/NPU 范围、回退、输出与质量等级 | SD3.5 已出图，所以 Cosmos 已出视频。 |
| 先做明确边界的混合烟雾任务 | 首层 Q、256行或4步是所有模型通用配置。 |
| 按来源与条件沉淀配方 | 一次成功经验等同于任意模型自动迁移。 |

[SD3.5 同期快照](../SD3.5_Medium/schedule_07.md) 的已证明范围仍是 Q-only HYBRID；扩大版也没有被本次归档为成功。两条模型工作线的执行证据不能互相代替。
