# schedule_03｜H3-Image 内存风险与当前可运行性核查

记录日期：2026-11-14。

前序快照：[schedule_01.md](schedule_01.md)、[schedule_02.md](schedule_02.md)。本文件新增第三份进度，不改写前两份记录。

**本阶段结论：现有 Qwen 文本生成启动方式不能直接替换模型目录后运行 H3-Image；将原始文本编码器、DiT、VAE 全部同时常驻 64 GiB NPU 的方案容量不足。分阶段加载、分层流送或低比特适配后能否跑通，仍未得到工程验证，不能提前承诺，也不能仅凭检查点体积判定硬件绝对不可能运行。**

本项目延续赛题5的本地模型迁移目标。本次只完成配置、既有日志、内存算术和公开上游代码的静态核查，没有连接 NPU 服务器、下载权重、安装依赖、启动服务或执行 H3-Image；没有新增出图、精度或性能结果。其他模型项目的里程碑不计作 H3-Image 的运行证明。

## 1. 当前可运行性分层判断

| 方案 | 本阶段判断 | 依据与边界 |
| --- | --- | --- |
| 将现有 Qwen 脚本的 `MODEL_DIR` 换成 H3-Image | 不能作为直接运行方案 | 脚本面向文本生成，不能替代图像流水线及后端接入适配 |
| 原始各组件权重同时常驻 NPU | 容量不足 | 上游组件文件合计约 135 GB，目标板卡总 DDR 为 64 GiB |
| 只保留原精度 DiT 常驻，其他组件分阶段执行 | 内存极紧，未证明可行 | 文件体积粗算只剩约 2.27 GiB，尚未核对实际驻留、工作区、复制和运行时保留 |
| 分组件／分层加载或磁盘流送 | 候选路线，未验证 | 需要具体前端、加载器和 Dope 执行链支持，不能仅套用 CUDA offload 说明 |
| W8／W4 等低比特 DiT | 候选路线，未验证 | 需要匹配的权重格式、量化计算内核、加载实现和质量验证 |

准确状态为：**待迁移、待适配、未取得完整运行证据**。不能写成已可部署，也不能写成已证明只能依靠某一种量化方式。

## 2. 内存数字复算

文件大小采用十进制 GB；设备日志采用 MiB／GiB。以下换算只用于容量估算，不是运行内存实测。

| 项目 | 输入数字 | 换算／含义 |
| --- | ---: | --- |
| 板卡 DDR 总量 | 65536 MiB | 64 GiB，板级总量 |
| DiT 检查点 | 66.28 GB | 约 61.728 GiB |
| 文本编码器完整检查点 | 66.7 GB | 约 62.119 GiB |
| 图像 VAE 检查点 | 2.34 GB | 约 2.179 GiB |
| 64 GiB 减去 DiT 文件体积 | 64 − 61.728 | 约 2.272 GiB；不是可用工作区实测 |
| 既有日志的 `Used` | 14824 MiB | 约 14.477 GiB；不是 14.8 GiB，也不是固定额外开销 |

仅权重文件就已逼近设备容量，说明原精度全量常驻路线具有真实风险。但文件体积不能直接当作运行分配：加载范围可能变化，权重重排、副本和工作区也可能增加占用。

主机约 59 GiB RAM 与 NPU 64 GiB DDR 是不同资源，不能简单相加后当作一个无约束的统一内存池。板卡总量也不证明每芯粒恰有独立、各自可用的 32 GiB；局部容量、跨芯粒寻址与分片约束仍待确认。

## 3. 对前一轮内存论证的修正

### 3.1 当前 `Used` 不是每个模型固定支付的池区开销

准确证据定位为本地原始文件 `board/dort-overview.txt:22`：

```text
Used : 14824 MiB (CalRT 22.6%)
```

`board/dort-device.txt` 不包含这个字段，不应用其行号引用该用量。板卡总量可定位到 `board/dort-board.txt:8` 或 `board/dort-overview.txt:9`。

这份快照不能单独证明：

- 14824 MiB 全部属于 Qwen2.5-0.5B，或全部属于某一个容器。
- 它只是运行时固定开销，而不包含权重、缓冲或其他分配。
- 后续 H3-Image 必须在该数值之外再额外预留同样大小。
- 当前设备仍保持该用量，或 `64 GiB − Used` 就是 H3-Image 能实际分配的容量。

若权重和激活已经分配在 CalRT 池中，再计算“权重＋激活＋整个池大小”会有重复计数风险。应核对真实驻留权重、同时存活激活、额外工作区／副本、池内空闲保留／碎片、运行时及外部作业占用，而不是把整个池作为独立额外项重复相加。

### 3.2 检查点体积不等于文本编码器必需驻留量

公开上游加载实现存在差异：

- **SGLang** 按所需特征提取层配置语言层范围，其加载器跳过不使用的后续层、`lm_head` 和最终 norm 权重。
- **当前 Diffusers** 读取 `hidden_states[50]`，不执行语言模型输出头投影，但所核查的代码没有据此裁掉完整层栈；代码还要求层数大于所选特征层，不能直接照搬截层做法。

因此，不能用“完整文本编码器文件 62.119 GiB 大于主机 59 GiB”就断言所有 CPU／分阶段方案都不可能；也不能反过来承诺普通 CPU offload 一定解决主机内存问题。必须分别计算最终驻留、构建／加载峰值、CPU 保留权重、磁盘映射和临时副本。

SGLang 在此仅作为加载策略参考，不表示其现有运行代码已支持 Calculet，也不表示把 Diffusers 的层数改成 50 就能保持数值语义。

### 3.3 不必然完整物化 QKᵀ，也不能笼统认定 DiT 必须使用掩码注意力

当前 Diffusers H3-Image DiT 通过 `dispatch_attention_fn` 选择注意力后端。源码说明单个请求打包成一个 attention document，默认路径不传入掩码；文本编码器及其他路径的掩码需求仍应分别检查。

注意力工作区取决于后端实现。仅作量级示例：若 2048×2048 对应 4096 个图像 token，并显式生成 56 个头的完整注意力分数，单个分数张量约为 BF16 **1.75 GiB** 或 FP32 **3.5 GiB**，尚未包含文本 token。这不是模型总峰值；使用分块／在线注意力时，不需要把该矩阵完整常驻。

因此，“激活一定需要某个固定 GiB 数”“完整 QKᵀ 一定同时存在”“DiT 一定被带掩码 SDPA 阻塞”都不能作为未经实现核对的定论。

### 3.4 Qwen 的量化包不能证明 H3-Image 已有相同能力

已有本地 `calbin/model_memory_reserved_info.txt:6` 标识的是 Qwen3.6-35B-A3B 的 W8A8-W4AF16 包，不是 H3-Image。其第 19—22 行声明的两个 DDR 参数区间合计约 **19.604 GiB**；对应 HF 索引的 `metadata.total_size` 约为 **66.965 GiB**。

这些是包内声明／索引信息，不是本轮读取完整权重文件所得的实测，也不是当前设备占用。它们支持“该 Qwen 包采用压缩权重”这一判断，不能证明任意 DiT 均可直接使用同一量化执行路径。

对 33.1B 参数做理想估算，纯权重 W8 约 30.8 GiB、W4 约 15.4 GiB；实际还存在混合精度层、尺度／分组信息、对齐和转换工作区。若加载时将全部低比特权重展开成 BF16，文件压缩也不等于设备驻留减少。

**本阶段未取得可直接用于 Calculet 的 H3 DiT W4／W8 官方适配证据。** 量化应被视为需要实现和验证的候选方案，而不是已确认的通用启动选项。

## 4. 接入与算子覆盖仍是独立阻塞项

- 内存方案成立，不等于图像前端和 Dope 后端已经接通。
- 现有 vLLM／Qwen 入口不能代替 Diffusers 或其他图像流水线的模型执行适配。
- `registry.lock.json` 的 accept／reject 应结合 dtype、布局、形状、分解及实际执行路径判断，不能仅从算子名称求一个文本差集就得到完整覆盖结论。
- 原始源码的静态枚举可以形成候选清单；完整执行图还需结合固定输入和相应的图捕获／追踪方法核对，区分准备元数据与核心计算。
- 其他项目已有的基础算子测试报告，不证明 H3-Image 的所有形状、精度、Attention、VAE 和整体流水线已通过。

## 5. 后续工作应形成的可验证结果

下列均为待完成事项，不是本次执行结果：

| 任务 | 输出物与验收边界 |
| --- | --- |
| 固定前端、模型版本、输入与采样设置 | 明确一条实际接入路径，不混用不同框架的加载假设 |
| 建立分阶段内存账本 | 分开列文本条件、DiT、VAE 的实际加载范围、峰值活跃张量、重排副本、池内保留及芯粒分布 |
| 对齐算子与精度支持 | 列出阻塞项及复现输入，核对布局／shape／量化内核，而不仅是包是否安装 |
| 决定容量方案 | 比较分组件、分层流送和可支持的量化方案；不先把 W4／W8 写成必然可用 |
| 授权窗口内验证 | 先关键算子／单模块，再固定 batch 1、原生 6 步的完整本地文生图；保留参考对比和设备轨迹 |
| 正确运行后优化 | 数值与质量闭环后再讨论融合、放置、内存池和性能；计时分开记录 |

本地静态分析可以排除不成立的部署方式，不能替代真实设备运行验收。当前不恢复服务器连接，不停止共享服务、不复位设备，也不修改原厂环境。
