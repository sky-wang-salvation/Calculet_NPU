## 4. SD3.5 Medium：历史真机成果与新离线成果

### 4.1 最高已确认模型成果仍是Q-only HYBRID

固定模型revision：`b940f670f0eda2d07fbb75229e779da1ad11eb80`；历史生成完成于北京时间2026-11-15约03:13，配置为256×256、batch1、4步、guidance1.0、seed20261115、无T5且保留两个CLIP。

| 执行位置 | 已记录范围 |
| --- | --- |
| **NPU** | 每步 `transformer_blocks[0].attn.to_q` 的全部256行；每请求16个M16分块，4次请求共64个tile；返回值进入真实后续去噪。 |
| **CPU/主机** | CLIP、除该Q外的DiT/Attention、scheduler、VAE、类型转换、传输与行组装。 |
| 精度 | CPU主要FP32；Q投影的输入、参数和输出BF16。未实施INT8/INT4整模型量化或NPU训练。 |
| 验收等级 | `HYBRID_IMAGE_GENERATED`、`core_migration_complete=false`；低步数烟雾预览，非正式画质验收。 |

这不是旁路NPU探针，但也不是完整Attention/DiT或主要计算全部迁移。“Q计算段零回退”不包括原本就在CPU运行的模块。

### 4.2 数值与性能口径

旧 `[16,1536]` BF16单元共24,576个元素，3个元素的位模式与保存参考不同；最大绝对误差 `0.000244140625`，RMSE `1.557344391530825e-06`，最大ULP距离4。状态仍为 `METRICS_ONLY / NOT_EVALUATED_NO_APPROVED_TOLERANCE`。数值工具本身不认证设备来源，不能将小误差直接写成正式通过。

历史整请求墙钟约99.798秒，不是纯NPU时间；主进程峰值RSS约17.94GiB，不是整机或远端worker合计；线程配置8不等于实测占满8个物理核。没有可发布的CPU/NPU计算百分比、同条件加速比或能耗改善。

### 4.4 392 Linear扩大版仍为UNKNOWN

392个Linear是静态候选清点；参数字节预算和8GiB池是代码配置，不是实际驻留或覆盖证明。仍缺同一次任务的最终回执、实际调用模块清单、扩大版图片、数值与资源关闭记录。

断连不能证明它成功、失败或停止。旧Q-only的四次关闭回执不能用于扩大版，更不能证明当前设备已释放。优先保留并核对原作业，不重复启动来替代查明结局。

旧静态calbin的 `BLOCKED_NATIVE_IO_DOUBLE_BUFFER` 也没有因eager成功而修复；成功图片采用逐算子eager路线。详见 [最新断连快照 schedule_10](https://github.com/sky-wang-salvation/Calculet_NPU/blob/154a3722f616d9014da8292f6f33484976fba612/experiment/SD3.5_Medium/schedule_10.md)。

## 8. 连接恢复后的优先顺序

以下为后续检查顺序，不是本次已经执行，也不意味着旧授权继续有效：

1. **先恢复获授权的登录入口并确认实际错误。** 不通过重复尝试凭据、关闭主机检查、改共享驱动或重启设备来猜原因。
2. **先查原任务，再决定是否新启动。** SD3.5扩大版、Cosmos既有下载/上传/生成任务分别核对持久ID、日志、输出、进程与资源回执，避免重复执行或覆盖证据。
3. **重新确认设备窗口和资源归属。** 历史健康、锁和关闭记录不代替当前现场协调，缺少锁文件不证明设备空闲。
4. **保留并复用已核验材料。** 只补缺失或身份变化的组件，不为连接故障重新下载全部模型、重算所有参考或覆盖旧运行目录。
5. **先验证最小真实任务。** Cosmos先取得固定 `proj_in` 的实际设备输出并与独立参考比较；SD3.5先核对扩大版原任务结局，再决定新的覆盖验证。不得以放宽回退或验收门槛制造成功。
6. **再形成统一Harness硬件闭环。** 让同一原生工具请求、服务任务、实际适配器、设备返回值和可读取产物对应，保留CPU/NPU分工、数值/画质等级和资源关闭记录。
7. **正确性和复现成立后才比较性能。** 分开准备、编译、加载、预热、传输、计算与端到端，不把总墙钟或测试数量当作NPU收益。
