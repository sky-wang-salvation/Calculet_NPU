# 原粒 NPU 五题调研：技术缺口、实现路径与选题

调研日期：2026-11-13（Asia/Shanghai）。本文是独立调研与工程建议，不是主办方正式补充规则，也不是实测性能报告。

核心判断：五题共同要求把芯片能力变成可复用的软件能力，分别对应**访存与调度效率、生成时的选择采样、模型语义兼容、应用端到端价值、新负载与开发工具**。“突破”可以是让缺失算子被图调用、修复真实模型语义、消除关键 CPU 回退或证明本地应用收益，无需先提出新的模型架构。

这里的“五题”是原粒赛道内的选题，不是整个 BoHack 的八个企业/主题赛道。

## 三个重要发现

1. 开发入口已经明确为 Rust 自定义工具链；`npu`、`calDNN`、`calBLAS` 分别承担原语、图接口、实现与样例。[SDK 主页](http://115.159.82.89/)
2. 公开 SDK 页面比 PDF 更强调视觉/多模态、端到端模型与 ComfyUI；其路线和评审措辞需与本届五题规则核对。[差异分析](03-sdk.md)
3. 仓库存在模板不等于已通过真机验证。必须逐一确认编译、原生代码生成、执行、数值和集成状态。[状态分析](03-sdk.md)
