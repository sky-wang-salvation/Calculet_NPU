# 题五：开放题、视觉模型与开发工具

## 开放题如何定义“创新”

题五允许应用、工具和计算任务，核心是明确问题、NPU 承担的计算与验收方法。创新可以来自新负载、接口桥接、可观测性或部署方式；需要最终可运行、有证据的工程成果。[赛题](../../赛题选择.md)

公开 SDK 页面给出更具体的方向：补齐视觉/多模态算子，尝试 Stable Diffusion、SAM、视频模型，以及原生前端的端到端 NPU 推理。页面还表达了对 ComfyUI 工作流的偏好。该描述来自公开入口，最终应确认与 BoHack 五题规则的对应关系。[SDK 页面](http://115.159.82.89/)、[规则差异](03-sdk.md)

## 三种突破层级

| 层级 | 可能的成果 | 价值 | 主要风险 |
| --- | --- | --- | --- |
| 算子族 | 补目标视觉模型缺失的归一化、卷积、布局等算子 | 扩展已有 LLM 算子库的负载范围 | 编译器/布局支持、逐算子数值 |
| 模型与前端 | 一个固定模型从原生入口请求到输出 | 减少用户迁移与使用成本 | 缺失算子多、模型语义和权重转换 |
| 工具 | 支持扫描、错误定位、性能报告、工作区优化 | 帮后续开发者更快获得可验证结果 | 容易停留在静态报告，缺真机闭环 |

## 五个可收敛的方向

**A. 小范围视觉模型移植。** 从目标模型计算图列出算子、形状、dtype、布局和动态行为，逐项对照 SDK。可从一个可执行子模块开始，但若声明完成整模型，必须覆盖完整路径。不要根据“已有 DiT 模板”就承诺任意扩散模型兼容。

**B. 固定工作流的 ComfyUI 后端桥接。** 限定一个模型版本、一条工作流、一个初始分辨率和固定采样设置；定义前端节点、模型加载、NPU 调用、结果回传及缓存生命周期。前端能显示图片不能证明计算在 NPU；需执行轨迹与逐阶段对照。扩展多尺寸放在基本出图稳定之后。

**C. SAM 类交互分割。** 将图像编码、提示编码、掩码解码分别清点，固定点/框提示集，评价 IoU、边界情况和交互延迟。是否能复用图像 embedding 需明确记录；重用缓存与首次图像编码是两种不同的计时场景。SAM 在这里是 SDK 页面建议的目标，不是已验证可部署型号。

**D. NPU 适配诊断与差分工具。** 读取目标图与当前引擎支持范围，生成可执行探针，定位第一个无法编译/数值不一致的阶段，输出复现包。工具应至少在一组真机执行上闭环；单独扫描代码而没有核心 NPU 计算，是否符合开放题需先确认。

**E. 低功耗常驻的小型任务。** 如视觉分类/异常检测或离线语音子任务。先选 SDK 可完整支持的模型，再固定数据、采样率/分辨率和质量指标，测持续运行能耗与尾延迟。这里只是候选方案，不表示当前平台具备对应模型支持。

## 为什么完整扩散/视频更难

端到端迁移通常横跨文本条件、主干网络、多轮采样和解码后处理。一个缺失算子会在每次迭代重复出现；部分 CPU 回退可能带来多次设备同步与搬运。输入分辨率或序列长度变化还会影响特化数量与 workspace。

对视频方向，应先统计有效帧数、空间尺寸、迭代步数、各阶段激活峰值和可编译算子；不能仅用显存容量或 TOPS 判断能否在比赛时间内交付。没有现成成功基线时，这是高风险选择。

## 给开放题一个可验收的表述

使用以下句式写选题卡：

> 在固定的输入、模型版本和设备上，用 NPU 执行明确列出的核心阶段，相比指定基线，在质量不低于约定门槛的条件下，改善指定的延迟/内存/能耗指标；交付可复现入口、原始结果和已知限制。

指标阈值应由基线测量与比赛合同决定，不在调研阶段虚构“至少提升 10 倍”等目标。最重要的退出条件是：若首个核心阶段在预留验证窗口内无法完成真机正确性，就缩小交付对象或转向已能闭环的算子路线，并同步修订验收目标。
