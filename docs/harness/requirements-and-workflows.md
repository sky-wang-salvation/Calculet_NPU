# 需求与工作流程

## 1. 用户已经表达的需求

1. 有一颗较少见的 NPU，希望常见 Agent 能使用它，当前选择 DeepSeek Harness 作为载体。
2. 已部署生成模型后，用户表达想要的图片/视频结果，系统处理调用、执行与产物交付，减少操作。
3. 对新模型，利用团队亲自迁移时沉淀的 Skills 协助获取、适配、部署与验证。
4. 探索从反馈改进后续执行的机制，体现 Built for Better；不能仅因加入记忆或 Skill 就认定应用有价值。
5. 必须说清真实用户、具体任务、发现的问题、方案、NPU 执行与优化位置、验证方式。

用户使用“训练”一词时，讨论尚未确认其指模型部署/推理还是实际训练/微调。首个验收合同应明确术语，不把推理支持自动写成训练支持。

## 2. 分工

| 部分 | 责任 | 当前边界 |
| --- | --- | --- |
| DeepSeek Harness 插件 | 能力发现、工具调用、任务状态、产物与反馈的组织 | 尚未实现与实际安装验证 |
| 本地文本模型 | 理解任务、规划工具使用、提炼候选经验 | 具体模型/接口、工具调用与效果要测试 |
| 多模态生成模型 | 生成实际支持的图像、视频等结果 | 不从一个模型推断全部模态和任务都支持 |
| NPU 后端 | 执行已适配核心子图/模型，提供可追溯执行证据 | 以当前版本、shape、精度和设备记录为准 |
| Skills/配方/安装包 | 保存可重复方法、条件、步骤与检查 | 固定流程优先作为确定性组件；不能单独充当应用价值证明 |
| CPU 工具 | 文件、分词、必要前后处理、排版与任务调度 | 如实列入端到端时间与处理器分工 |

官方 Harness 提供模型适配器、工具与事件扩展的设计入口，参考[架构文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)、[模型适配手册](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/adding-an-llm-adapter.zh.md)、[工具手册](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/adding-a-tool.zh.md)。这些是已阅读的方案依据，最终开发须固定版本；本项目未证明接口已对接。

## 3. 工作流 A：使用已部署模型

用户给出任务与输入 → 查询已验收能力 → 规划任务 → 提交 NPU 作业 → 等待/取消/失败处理 → 保存和组织产物 → 用户检查结果。

工具输出应包含任务状态、模型与版本、产物位置、设备执行证据和错误，而不是只返回一句“成功”。自然语言需求转换不得静默改变用户规定的分辨率、质量或计算范围；不支持的要求应明确暴露。

用户价值取决于最终结果和操作负担：可以测完整完成率、人工介入、返工和交付时间。生成阶段的 NPU 性能另外比较。

## 4. 工作流 B：新模型部署与适配

确认目标模型/入口/验收 → 匹配已验证配方 → 检查依赖和资源 → 探针验证 → 必要适配 → 真实权重与子模块 → 完整任务验收 → 注册为可调用能力。

至少区分：已有可验证配方、部分复用、发现新缺口、完整验收通过。需要工程师解决的新算子缺口可以生成最小复现，但不能把错误分析称为已经自动完成迁移。

该工作流作为支撑工具保留。用户已指出固定问题可以由安装包/补丁/Skill 解决，不能反复将此包装成新的独立产品需求。

## 5. 反馈学习作为可验证机制

一种尚待实现的设计是：任务结果与反馈 → 候选经验/策略 → 在固定检查与保留任务上验证 → 版本晋升 → 下一次任务采用 → 退化时回退。

| 内容 | 应记录什么 |
| --- | --- |
| 经验 | 来源任务、反馈、适用用户/模型/SDK/shape、影响的决策 |
| 变更 | 旧版本、新版本与具体变化 |
| 验证 | 预先定义的指标、未参与学习的任务、通过与失败 |
| 应用 | 下次任务是否调用，影响了哪个动作 |
| 回退 | 恢复旧状态的入口及可核对结果 |

这是一项设计，不是已完成的 RSI。仅增加日志、把一次修复保存成 Skill、或让模型自称进步，都不足以证明后续任务改善。权重训练、自动改代码和在线试验也没有得到“当前已经支持”的结论。

## 6. 参赛定位

正式参赛仍选择一个企业赛道。用户提供的特别激励面向满足主题原则的企业赛道项目，不等于同时报名主题赛道。两次完整运行、展示学习变化、可回退可作为保守设计目标；特别激励具体验收流程仍须赛事确认。

核心推理按比赛本地实现要求设计。下载公开模型或文档与用云端推理替代本地计算是不同动作；任何实际执行按授权、设备窗口和资料范围处理。本设计文档没有触发这些动作。
