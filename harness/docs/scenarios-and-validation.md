# 用户场景与验收：从任务结果看 NPU 价值

完整场景表与五题解释见 [13-scenarios-and-value.md](../../docs/research/13-scenarios-and-value.md)。本页保留便于交接的简表；所有场景仍是候选设计。

## 1. 问题—方案—设备工作—验收

| 用户/任务 | 发现的问题 | 方案与交付 | NPU 核心计算 | 关键验收 |
| --- | --- | --- | --- | --- |
| 策划/导演：脚本变分镜板 | 拆镜头、生成、整理重复，脚本要求易遗漏 | 本地模型规划，组织候选图生成，交付分镜板与源文件 | 图像网络；文本规划若接通也记录设备阶段 | 合格镜头、漏项、返工、完整交付时间 |
| 仿真测试：失败条件变补测候选 | 人工制作/寻找和筛选耗时，条件重复遗漏 | 提取缺口，调用已支持条件的生成模型，交付片段与覆盖记录 | Cosmos 视频网络中已适配阶段 | 独立接受的有效片段、覆盖与准备时间 |
| 售后：故障描述变资料证据 | 型号/版本混淆、查找和排序不佳 | 公开/合成资料本地检索、重排并列出处 | 编码器或重排模型前向 | 找对文档/版本、排序质量、查询时间 |

第一项贴近 H3-Image，第二项贴近 Cosmos；第三项主要作对照，需额外模型，不能为覆盖所有题扩大当前实现。

## 2. 与五题对应

| 赛题 | 具体技术问题 | 改进与证据 |
| --- | --- | --- |
| 一 | 连续计算的中间读写和启动开销 | 融合指定运算；原始/优化 NPU 路径正确性和资源对照 |
| 二 | token 候选选择、过滤和抽样 | NPU Top-K/Top-P 等；选择语义、随机分布和整体耗时 |
| 三 | 模型语义/shape/布局与后端不匹配 | 固定特性的真实适配、参考比对、支持范围 |
| 四 | 本地检索或重排任务 | 核心阶段实际用 NPU，质量与端到端评价 |
| 五 | 自定义完整用户任务 | 可运行产物、验收标准、NPU 贡献和复现 |

扩散去噪的“采样步骤”不自动属于题二的 Top-K/Top-P；必须按实际计算判断。前三题可为应用提供底层增量，但不要求每个应用同时实现五题。

## 3. 四种收益分别比较

| 要证明的收益 | 对照 |
| --- | --- |
| 用户操作减少 | 用户原有流程 vs Agent 完整流程 |
| NPU 使用有价值 | 同模型、输入与质量合同下 CPU vs NPU；不宣称 NPU 独有该功能 |
| 本队优化有效 | 原始 NPU vs 修改后的 NPU，保持语义和输入 |
| 学习改善后续任务 | 学习前后策略，固定评价，另测保留任务并演示回退 |

缓存、预热、模型更换、精度改变和人工提前准备都单独记录。无法测能耗时标“未测”，不以板卡标称功率代替。

## 4. 反馈学习最小验收

第一次完整任务 → 正常用户反馈/真实错误 → 系统提出策略变化 → 检查后保存版本 → 第二次完整任务自动使用 → 查看变化与回退。

检查三件事：学到了什么具体内容；它改变了哪个动作；后续任务是否因此改善。新记忆条目数量不等于学习效果。用户正常评分/纠错与人工改代码/提示词不同；现场规则按组委会确认口径执行。

## 5. 商业判断要由用户任务支持

采用理由可以是假设：更快拿到有效提案、更快补齐有效测试片段、更少查错资料。它们都需要与真实用户当前方式比较；没有访谈或试点前不宣布付费意愿。

同样需要允许否定结果：若固定脚本同样完成任务且更简单，或硬件/模型表现不能满足需求，就不把加一层 Harness 当作价值证明。
