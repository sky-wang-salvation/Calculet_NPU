# 第五题部署闭环验收合同

日期：2026-11-15。本文是验收要求与证据分层，不是已经通过真机复测的声明。赛题依据为仓库内《BoHack 2026 赛道和赛题设置》的原粒第五题及统一规则。

## 1. 作品边界

作品是面向原粒 NPU 的自然语言部署与验证开发工具。首版使用 DeepSeek Harness 原生工具和 `calculet.task/v1`，只支持已配置 SDK 的获授权环境与 SD3.5 首层 Q 投影 HYBRID 档案。

| 起点 | 终点 |
| --- | --- |
| 厂商 SDK 已配置；团队适配器、模型组件和设备使用窗口须另行绑定 | 有身份和范围明确的任务计划、实际适配器执行结果、分层验收、可调用能力和可读取产物 |

不能把预先已部署模型的一次生成调用称作从空环境完成部署。安装厂商驱动、修改 SDK、任意模型适配、全模型 NPU、训练和自进化不在首版承诺内。

## 2. 三层测试不得混用

| 层次 | 执行对象 | 能证明的内容 |
| --- | --- | --- |
| 纯合同测试 | TaskSpec、响应解析、原生工具、回环 HTTP | 字段约束、身份一致、状态与异常处理 |
| 模拟适配器集成 | 独立测试进程，明确 `simulation` | 计划、异步作业、落盘、幂等、产物访问和恢复流程 |
| 授权真机验收 | 团队真实适配器、真实权重、获准 NPU | 实际设备计算、真实输出和原生入口等价性 |

前两层通过不意味着第三层完成。关闭遥测不能阻止规划模型 API 自身发送上下文；非公开厂商资料不得进入外部 AI 工具。

## 3. 首版验收矩阵

| 检查 | 预期结果 | 所需证据 |
| --- | --- | --- |
| 受支持自然语言目标 | 生成保留用户硬约束的 TaskSpec；正常完成后交付实际输出 | 原始目标、工具调用、规范化 spec、计划、作业和产物 |
| 未支持模型或参数 | 在执行前拒绝，不静默变更模型、shape、精度或执行范围 | 错误码；未创建设备执行的记录 |
| 明确要求全 NPU | 拒绝当前 HYBRID 配方 | 输入约束与 `UNSUPPORTED_DEPLOYMENT_PROFILE` |
| 缺少适配器或授权 | 计划 blocked，不能提交真实执行 | 阻塞原因和零执行记录 |
| 计划过期或绑定变化 | 应用计划失败，不运行旧绑定 | 计划摘要、有效期、变更对象和拒绝记录 |
| 重复提交 | 同键同请求返回同一任务；同键不同请求拒绝 | 幂等键、作业 ID、适配器启动次数 |
| 停止等待 | 结束前端轮询，保留原任务，不伪称后台取消 | 前后 GET/POST 记录及原 ID |
| 服务重启遗留任务 | 核对未知副作用，不盲目重启设备计算 | 原任务持久记录、reconciling 原因 |
| 适配器失败 | 非零退出、缺结果、身份或哈希不一致不能变成成功 | 退出码、错误、保留日志和终态 |
| 产物路径越界 | 拒绝目录穿越、符号链接逃逸和非本任务产物 | 拒绝用例，不泄露其他文件 |
| 真机/仿真混用 | 模式不一致拒绝；测试结果始终标 simulation | 请求、适配器报告、作业和呈现标签 |
| 原生入口等价 | 固定版本、输入、精度和配置下与原生程序结果按同一合同比较 | 原生与 Harness 运行记录、独立比较结果 |
| 自然语言规划 | 官方 Harness 聊天实际选择工具并完成流程，不由人工直接点接口代替 | 获准规划模型配置、脱敏工具轨迹 |

## 4. 硬件计算与验收等级

当前已知历史样例为256×256、4步、无T5；每步首层 `transformer_blocks[0].attn.to_q` 的256行由NPU返回，其他主要模型阶段仍在CPU。此范围应在任务、执行报告与展示中一致标注为HYBRID，`coreMigrationComplete=false`。

| 结论 | 必须具备的依据 |
| --- | --- |
| 工件身份一致 | 完整组件/输入/源码清单与内容摘要 |
| 真实 NPU 执行 | 明确实际后端、设备运行记录、结果来源和计算段回退记录 |
| 数值通过 | 独立参考、适用的累加/舍入合同和预先批准容差 |
| 烟雾图成功 | 约定形状与格式、可读取的真实输出、链路与来源证据 |
| 正式图像质量通过 | 单独批准的质量合同与评价结果，不能由PNG存在推导 |
| 性能改善 | 同输入和同质量条件下的可比测量，不用HTTP等待时间代替kernel时间 |

`METRICS_ONLY` 或 `NOT_EVALUATED_NO_APPROVED_TOLERANCE` 不能改写为精度通过。适配器报告与哈希校验也不能替代独立硬件认证。

## 5. 每轮真实验收包

至少保留：

- `task-spec.json`：原任务合同及字段来源。
- `plan.json`：已冻结计划和运行绑定摘要。
- `job.json`：状态、阶段、时序、错误与恢复记录。
- 适配器实际执行源码摘要和组件清单；日志中的凭据必须脱敏。
- 原生入口与Harness入口的实际参数，避免未使用用户prompt/seed却报告成功。
- 真实输入/输出指纹、设备记录、回退计数和必要原始证据的获授权引用。
- `metrics.json`：参考比较口径、误差和批准容差；未批准时明确未评估。
- 真实PNG与 `evidence.json`：CPU/NPU分工、验收等级、限制及完整性索引。
- 分开的准备、编译（如适用）、加载、预热、传输、计算和端到端耗时。

私有SDK与敏感日志可按厂商许可保留受控访问，不以公开发布为默认前提。比赛评委必须能按获准方式复核，不能只看到不可访问的私人绝对路径。

## 6. 开发工具的收益如何测

固定相同任务和完成标准，分别运行手工入口、固定脚本与Harness路径，记录人工介入次数、主动操作时间、失败定位时间、重复执行次数和有效完成率。固定脚本已经能完成且更简单的情况应如实说明。

相同缓存二次运行变快不等于学习。主题赛道的自进化演示不是原粒第五题的默认必选项。

## 7. 合规与提交清单

- 不能用远程生成服务替代本地实现；说明规划模型、执行服务与实际计算的位置。辅助外部模型是否被允许，以现场解释为准，不默认合规。
- 真实设备按安排使用；SDK已配置不是设备使用窗口。禁止抢占、擅自刷写或复位。
- 不上传非公开资料到外部AI；展示厂商资料前经工程师确认。
- GitHub交付团队代码、锁定版本、测试、无密钥配置、运行方法、结果和限制；不提交node_modules、Token或未获准SDK。
- 通用提交含仓库链接、路演PPT、项目说明；按硬件项目要求准备不超过3分钟的演示视频。

只有对应证据完成，才将该项标为已验收。未执行的真机、规划模型或性能检查保持明确未验证，不由测试数量替代。
